# Worked FK / IK Example

This example uses the repository's documented analytic kinematics implementation with a reachable target and a software-only round-trip check. It is intended to make the coordinate and angle conventions concrete before using the physical-arm workflow.

## Inputs

Use the default model geometry:

- Base height: **30 mm**
- Link 1: **100 mm**
- Link 2: **80 mm**
- Base yaw: **20°**
- Shoulder pitch: **35°**
- Elbow pitch: **−50°**
- IK branch: **elbow_down** (`elbow_up=False`)

The angles are the `JointAngles` convention used by [`src/arm3dof/kinematics.py`](../src/arm3dof/kinematics.py):

- `base` rotates the arm around the vertical axis.
- `shoulder` and `elbow` are planar pitch angles.
- Positive Z is upward from the base-height reference.

## 1. Forward kinematics

For the joint angles above, the implementation computes:

| Quantity | Value |
| --- | ---: |
| X | **149.588983 mm** |
| Y | **54.445937 mm** |
| Z | **66.652120 mm** |

The corresponding Cartesian target is therefore:

`(149.588983, 54.445937, 66.652120) mm`

This value is generated by the actual `forward_kinematics()` implementation rather than by a second formula maintained in this document.

## 2. Inverse kinematics

Pass that Cartesian target to `inverse_kinematics()` with the same geometry and `elbow_up=False`.

The solver recovers the same joint configuration to floating-point precision:

| Joint | Expected |
| --- | ---: |
| Base | **20°** |
| Shoulder | **35°** |
| Elbow | **−50°** |

The solver can represent other valid configurations for the same target; this example selects the documented elbow-down branch so the result is deterministic.

## 3. FK reconstruction check

Run forward kinematics again using the recovered IK solution.

The reconstructed position is:

`(149.588983, 54.445937, 66.652120) mm`

For the repository's regression test, the round-trip position comparison uses an absolute tolerance of **1e−7** in the model's length units.

The existing test [`tests/test_kinematics.py`](../tests/test_kinematics.py) performs the same FK → IK → FK consistency check programmatically.

## Reproduce it locally

Install the package and run:

```bash
pip install -e .
pytest -q tests/test_kinematics.py
```

You can also inspect the CLI implementation in [`src/arm3dof/cli.py`](../src/arm3dof/cli.py) and run the FK/IK commands shown in the main README.

## Evidence boundary

This example verifies the **software kinematic model only**.

It does **not** establish:

- physical endpoint accuracy;
- servo calibration accuracy;
- backlash or repeatability;
- payload capability;
- mechanical tolerances;
- physical safety.

Those remain separate measurement gates documented in [`docs/PHYSICAL_VALIDATION.md`](PHYSICAL_VALIDATION.md).
